# 2026-10-24

## Agents and Docker found wherever their installers put them

**What changed**: on Windows 11 (beta.4), an agent installed while Codemm was open stayed "Not installed" until a restart. Codemm read `PATH` only at launch, and its lookup missed several official install folders. This is the first of several PRs for zero setup friction on macOS and Windows.
- **Windows live PATH** (`desktop/src/main/agent/livePath.ts`). Before Connect's list, Connect, Check this computer and each job's start (`live.ts`), Codemm reads the machine's and the user's `Path` with `C:\Windows\System32\reg.exe` as argument arrays. It expands REG_EXPAND_SZ `%NAME%` from its environment, ignoring case, and appends the missing folders to `process.env.PATH`, so jobs and core's docker calls inherit them. What PATH had is never removed or reordered. Calls at the same time share one read, and a read under 2 seconds old is reused. A read that fails or takes over 2 seconds keeps the PATH. Off Windows it does nothing. `find` stays synchronous.
- **More folders** (`find.ts`): WinGet's command links (`%LOCALAPPDATA%\Microsoft\WinGet\Links`, `%ProgramFiles%\WinGet\Links`), Cursor's `%LOCALAPPDATA%\cursor-agent` (its `.cmd` is still passed over until the Cursor-launcher PR), Docker Desktop's per-user CLI folder on Windows (`%LOCALAPPDATA%\Programs\DockerDesktop\resources\bin`), and `~/Applications/Docker.app/Contents/Resources/bin` on macOS. Docker Desktop's helper folders are now `dockerDesktopBins(where)`.
- **npm shims for a native binary**: `shimTarget` takes the quoted path just before `%*`. A `.exe` target runs directly, which finds Claude Code installed with npm (its `bin` is `bin/claude.exe`). The JS shim's `IF EXIST "%dp0%\node.exe"` line is no longer a candidate.
- **macOS `~/Applications/Docker.app`** (`dockerDesktop.ts`): counts as installed, Open Docker Desktop opens it, and Install Docker opens an existing Docker.app from either Applications folder instead of downloading.
- DESIGN (desktop) §3.1 and §6.1 say so.

**Verified**: tests written first and seen failing. Desktop typecheck passes, and so do the affected tests on macOS (livePath, find, dockerDesktop, the new `live.path` tests, every `live.*` file, connect, computer, agent, agentInstall, server and mock). New tests:
- reg output parsing, expansion, merge and dedupe;
- one shared read, a young result reused, the PATH kept when reg fails or hangs past 2 seconds, and a merge that never shrinks or reorders PATH;
- fixture trees for WinGet, Cursor's folder, the npm `.exe` shim (cmd-shim's real no-shebang template), Docker per-user and `~/Applications`;
- through the live API: an agent and a docker that appear only in the registry PATH after start show on the next `agents()` and `computer()`, and a job refreshes before it starts.

**Not verified**: nothing has run on a Windows PC yet. The Windows unit tests run only in CI.
