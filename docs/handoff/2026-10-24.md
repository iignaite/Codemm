# 2026-10-24

## Change the agent from the sidebar, and see installs live

**What changed**: on Windows 11 (beta.4) Connect stayed on "Not installed" after agents were installed, and once an agent was connected there was no way to change it. This is the UI half of the fix; #228 makes each lookup read Windows' live PATH and more install folders.
- **Agent in the sidebar.** One entry, "Agent" with a plug icon, in the wide and the slim sidebar. It uses the same nav item as Learn, Practice and Tracks, and opens Connect with `then` set to the screen it left.
  - Connect on another installed agent switches to it, and the one before shows Connect again at once.
  - Continue goes through Check this computer, which moves on by itself, back to that screen. The course editor comes back on its saved draft (`editorRoute`, shared with WorkNow), so its edits survive the trip.
  - A click whose draft read is overtaken by the learner moving on does nothing.
- **Switching underneath already worked**: a running job keeps its agent, the next job uses the new one, and tutor sessions are kept per course and agent. A new live test covers a switch mid-course.
- **Live looks.** Connect re-reads the agents every 3 s while shown (`timing.agentsMs`; every 0.5 s while an install runs) and on focus. Welcome and Setup re-read every 3 s until an agent is connected; Setup goes on to Connect once nothing is left to install.
- **`useLoad`** gained an `idle` option (the poll once settled). It now drops a read that a `reload()` overtook, since that read began before the change: otherwise a poll in flight while the learner connects would flash the old state. A timed re-read waits while the window is hidden (minimized or covered) and runs once it shows, so a minimized Connect doesn't keep starting an agent's status command.
- **Auto-connect.** Connect's check of the only supported installed agent now runs on the first look that finds one, so an agent installed in a terminal while Connect is open connects (or asks to sign in) by itself. Still once, and never while another agent is connected.
- **Sign-in checks (`connect.ts`).** Each check starts the agent, so:
  - a look checks an agent's sign-in again only 5 s after its last check ended (`RECHECK_MS`); this replaces `justChecked`;
  - a look or a job joins a check still running (so Welcome never shows a relaunch's signed-out agent as connected), and Connect waits for it and asks again;
  - one look shows only one agent connected;
  - an agent Codemm installed connects once signed in only if the learner hasn't tried another since.
- **Sign-out stall loop (`live.ts`).** A look that finds an agent connected again now ends sign-out stalls, through the same helper `connect()` uses (`signedInAgain`). Before, signing in elsewhere left the stall, and Continue sent the learner from the course map to Connect and back for good.
- **Mock.** It re-reads `options.agents` on every look, and clears a sign-out stall as main does. `later.after: 'look'` and the `agent-found-later` scenario show Claude Code appearing in the mock app (`CODEMM_MOCK=agent-found-later`).
- DESIGN (desktop) §1 Navigation, §3.1 (Looking again, Changing the agent) and §6.1 Moving on say so.
