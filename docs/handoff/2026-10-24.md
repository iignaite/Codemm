# 2026-10-24

## Docker Desktop and WSL on Windows without the installer's prompts (branch `fix/windows-docker-wsl`)

What changed:
- Docker's Windows install is now Docker's own per-user install, unelevated: `install --user --quiet --backend=wsl-2`. No permission prompt, no installer window, no install-type page. No `--accept-license`: Docker's Accept stays in Docker Desktop's first window (DESIGN §6.1, item 5). An existing Docker Desktop, for all users or this one, is never installed over. Exit 1603 and every other non-restart code is "failed".
- New `desktop/src/main/wsl.ts`: reads firmware virtualization and the hypervisor (PowerShell CIM, once per run), WSL's presence (`%ProgramFiles%\WSL\wsl.exe`) and version (`wsl.exe --version`, `WSL_UTF8=1`), and runs WSL's own setup (`--install --no-distribution` or `--update`) as administrator through the .NET `runas` script that moved here from `dockerDesktop.ts`.
- Install Docker on Windows runs WSL's setup first when it's needed (one prompt), then Docker's install, then asks for a restart instead of opening Docker. Check this computer's running row names the real cause (WSL missing, WSL old, virtualization off, restart pending) instead of "Docker is starting" or Open Docker Desktop, with Set up WSL, Update WSL or Restart now. `restartWindows` is a new IPC call: `shutdown.exe /r /t 0`, on the learner's click only.
- Not done, on purpose: reopening Codemm after the restart (HKCU RunOnce) is an owner decision, listed in DESIGN §12. `Setup.tsx` is unchanged (another session owns it), so Setup's Docker card shows the restart line without a Restart now button for now.

How it was verified:
- Test-first unit tests: `wsl.test.ts` (parsing UTF-8, UTF-16 and localized output, each state, the elevated arguments, nothing elevated when nothing is needed), `dockerDesktop.test.ts` (argument array, no runas, exit codes, WSL first, no reinstall), `computer.test.ts` (each WSL cause replaces starting), renderer `computer.test.tsx` and `setup.test.tsx` (each state's screen; nothing restarts without a click).
- CI's Windows runner runs `wsl.test.ts`'s real-command test, which records what the runner's WSL and CIM answer without hanging.
- Not confirmed on a real PC: the exit code of `wsl --install --no-distribution` on a PC without WSL, whether `HypervisorPresent` turns true after the restart on every PC, and Docker's per-user installer's behavior on a PC without WSL (CI showed exit 0 on a runner).

What's next:
- On the owner's Windows 11 PC: Install Docker from a PC without WSL (one prompt, one restart), and a PC with virtualization off in firmware.
- Once the Setup screen's owner merges: a Restart now button in Setup's Docker card, and the WSL step there instead of Open Docker Desktop.
