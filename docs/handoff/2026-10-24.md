# 2026-10-24

## Cursor's CLI on Windows

**What changed**: on Windows, Cursor was never found, even after a relaunch. Its `cursor-agent.cmd` is a PowerShell 5.1 launcher, not an npm shim, and Codemm can't run a `.cmd` without a shell. `agent/cursorWindows.ts` now resolves Cursor's install root to `versions\<v>\node.exe` and `versions\<v>\index.js`. `Executable` takes optional leading `args` and `env`, and `bridge.command` builds every launch from them, for jobs, status checks and Sign in. Cursor runs as `node.exe [--use-system-ca] index.js …` with `CURSOR_INVOKED_AS=cursor-agent`, as its macOS launcher does. `find.ts` sends a `cursor-agent.cmd` beside a `versions` folder to the resolver. DESIGN (desktop) §3.1 says so.

**Verified**: tests written first: resolver fixture trees (one version, several, timestamped, `.new`/`.previous`/temporary, a missing `node.exe`, a `.ps1` that names a version, none), the cached `--use-system-ca` probe, `spawnable` and `command` with the prefix, Sign in for Cursor on win32, and a real child that gets a brief with newlines, quotes, `!`, `%PATH%` and backticks byte for byte (CI runs it on Windows too). Desktop typecheck and the affected test files pass on macOS.

**Not verified**: a real Windows PC. Cursor's real `cursor-agent.ps1` hasn't been read, so the version choice is to confirm. Also to confirm: whether its Node takes `--use-system-ca`, and a full Cursor job and sign-in on Windows.

**Next**: confirm on a Windows PC or the CI install matrix. Codemm installing Cursor is a separate PR.
