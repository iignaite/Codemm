# 2026-10-27

## Practice without Docker (the WASI engine)

**Why**: students on school computers can't install Docker, because they have no admin rights, so Codemm couldn't run any of their code. The owner chose a WASI fallback for 1.0.2: io practice in interpreted languages, with wasmtime bundled in the desktop app.

**What changed** (DESIGN §4.5): five PRs, built in parallel sessions against one contract, each with its own Opus reviews.
- #258, the contract. An Opus review of it found 12 must-fix gaps before implementation: precompiling, wasmtime's own failures, the Windows seal, macOS renames, an optional sha256, the engine trigger, the desktop's env, the type shapes, error codes, school proxies, unpacking, and ambiguities.
- #260, the engine: `src/wasi.ts`, the judge, Run and `doctor`. Language-free WAT tests, and a pinned wasmtime in CI on all three operating systems.
- #261, tracks: the track.yaml `wasi` block, toolchain download, verify, unpack, precompile and store, gates, install and rebuild. There's an end-to-end test with real wasmtime.
- #262, desktop: wasmtime bundled per platform (pinned SHA-256), `CODEMM_WASMTIME` passed to every core process, a download over Electron's `net.request` (system proxy and certificates), the Computer screen's no-Docker path, and the entitlements for signed macOS builds.
- #259: the agent's track rules, an MCP note on which engines the computer has, README, SECURITY and architecture docs.

**Windows**: it took several CI rounds to find a seal wasmtime can open. The answer is one inherited deny entry, `(OI)(CI)(WD,AD,WEA,WA,DC)`.
- Generic `W` also denies `SYNCHRONIZE` and `READ_CONTROL`.
- wasmtime asks for `DELETE` when it opens a folder, and wasmtime and Node both ask for it when they open a file, even to read it.
- Folders keep their mode, because the read-only attribute stops wasmtime opening them.
- CI proves on Windows that create, truncate, mkdir, unlink, rename, and deleting a folder that holds files are all denied.

**Verified**:
- CI is green on every PR: unit tests on Linux, macOS and Windows, both Docker suites, and desktop on macOS and Windows.
- On main, with the built CLI on macOS: a real CPython 3.15.1 WASI track installed in 9.5 s. That covers the download, the sha256 check, unpacking, precompiling, and the pass, fail, fast and determinism probes.
- The stored toolchain is read-only, and adding a file to it is refused.
- `doctor` shows both engines.
- Docker tracks (`custom-unit`, `shell-io`) still install on the same build.
