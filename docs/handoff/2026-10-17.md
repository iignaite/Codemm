## Post-1.0 fixes from the live E2E

A full local E2E with Claude Code (C track, roadmap, gated exercise, learner flow, practice hook, assist mode) found two defects. Branch `fix/e2e-starter-check-and-digest`.

- **Starter checks.** `checkExercise` grades a check whose learner files are byte-identical to the starter but doesn't record it (`recorded: false`, `note`). Before, starter check + one real wrong attempt reported `stuck`. The learner rules are unchanged (A8 holds: nothing enters the log). DESIGN §7 and §8.
- **Digest pinning.** `unpinnedBases` (gates) lists `FROM` images without `@sha256:`, skipping `scratch` and earlier stages. `save_track` / `codemm track add` still install, with a `warning`. Rejecting was not chosen: checks run by image ID and rebuild re-runs every gate, so an unpinned base can only make a rebuild fail. DESIGN §4.4 and §8.
- **Review.** Astra found three issues in the first draft and one in the re-check, all fixed test-first: an unrecorded starter check skipped the sticky `assist` event and the `current` update, `FROM ${ARG}` with a pinned default was falsely warned, and so was a `FROM` continued onto the next line.
- **Verified:** failing tests first (`test/gates.test.ts`, `test/docker/app.test.ts`), then `npm run typecheck`, `npm run test:unit` (155) and `CODEMM_REQUIRE_DOCKER=1 npm test` (210) locally.
- **Next:** none required. The 1.0 release evidence ("the unedited starter fails and is recorded") describes 1.0.0 as shipped and was left as is.
