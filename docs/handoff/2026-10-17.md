## Environment states in the core

Branch `claude/core-env-states-d5636f`. The core now behaves well when a learner's Docker is missing, stopped, offline or out of disk.

- **Doctor wording.** Docker installed but not running now says to start it (`startHelp`), per OS. "Not installed" is unchanged, including for a configured CLI that doesn't exist.
- **Empty tracks.** `codemm tracks` prints one line when none are installed.
- **Docker lost mid-run.** After a non-zero driver exit, the judge asks the runtime whether it's still up. Exit 125 after partial output is also treated as a runtime failure. Either way nothing is graded or recorded, and the message says the run wasn't counted. Before, a check that lost the runtime after one frame was graded as all `error` and recorded.
- **Track install offline, low disk or no runtime.** `buildImage` reports `problem` for these (`buildProblem` reads the build output), and `verifyTrack` throws a plain `CodemmError` instead of `Gate "build" failed`, saying the track files aren't the problem.
- **Fake Docker.** `test/fixtures/fake-docker` is a shell script that `test/fake-docker.ts` puts on a temp PATH. It runs on POSIX only, so on Windows only the "missing" scenario runs.
- **Review.** Astra found two issues, both fixed test-first: `could not resolve` also matched npm ERESOLVE and bundler import errors, and a run that lost the connection was still graded if Docker came back before the probe. The re-check found nothing.
- **Verified:** failing tests first, then `npm run test:unit` and `npm test` with Docker locally, plus a before and after `env -i` simulation (in the PR).
- **Next:** with `env -i` and a fresh `HOME`, the Homebrew `docker` CLI has no buildx, so `--progress plain` fails as `Gate "build"`. A real learner HOME has buildx, but a CLI without buildx would hit this. This needs a follow-up.
