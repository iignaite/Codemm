- **Codes, not wording.** Every error for this computer's problem carries a stable code (`src/errors.ts` `INFRA`, via `infraError`), and its kind follows from it. `codemm mcp` writes `codemm:<code or kind>` as a failed tool result's first line, and a write that runs out of space is `host-disk` there. The judge, Run, inspect, list, the leftover cleanup and the desktop's probe (`wire.ts`) use them. "Stopped" is said only when the runtime says so; it names a paused Docker Desktop, socket permission and a CLI context pointing elsewhere.
- **Named refusals.** `docker run` exit 125 is named in fixed phrases (`startRefusal`): fewer than 2 CPUs, the logging driver, file sharing, Docker's disk, the network. The CLI's text never leaves. Exit 126/127 before the driver printed anything is the track image's (no `/bin/sh`). A flood is graded before a slow removal. The memory-kill lookups wait 60 s.

- **The desktop says which.** Stopped, "Docker is busy or not answering.", "Docker couldn't run that. Try again, and restart Docker if it happens again.", "Docker ran out of disk space." (Docker's) apart from "Not enough disk space" (this computer's), and a rebuild stall with Go to Tracks. A failed setup offers Stop for Docker problems. A cleanup failure is Docker's, not the agent's. Try it's failure says "Try it didn't run".

## Install and sign-in on learners' Macs and Windows PCs

Branch `claude/pensive-wilbur-f3a8e3`. Fixes from the install scenario hunt (H1 to H17), in `desktop/src/main` and DESIGN §3.1, §5, §6.1.

- **Downloads** (`download.ts`, new). Docker and the agents now download through Electron's `net.request`, so the system's proxy and certificate store apply. Every redirect hop is checked before `followRedirect()`. (`net.fetch` can't do this: with `redirect: 'manual'` it fails with "Redirect was cancelled".) The 45-minute total deadline is gone. No bytes for 60 s, or a network error midway, is offline. A disk error, a size cap or an HTTP error is a plain failure. Node's `fetch` stays only for the opt-in real tests.
- **Chip.** `nativeArch` asks Electron (`app.runningUnderARM64Translation`), so an x64 Codemm under Rosetta or Windows' x64 emulation downloads arm64 Docker and Claude Code. On Windows, Electron asks for the native machine (`IsWow64Process2`). `PROCESSOR_ARCHITEW6432` is a WOW64 variable for 32-bit processes, and Microsoft says an x64 app can't tell it runs on Arm without such an API.
- **OS check before the Docker download.** `sw_vers -productVersion` must be 14 or later. On Windows, `reg query` of `CurrentVersion` must give build 19045 to 21999, or 22631 and later, and not Server. These are Docker's release-note minimums (4.48, 4.49). New problems: `macos-version` and `windows-version`. An unreadable answer lets Docker's installer decide.
- **Windows Docker install.** It runs elevated: PowerShell calls .NET's `Process.Start` with the `runas` verb, the path in `$env:CODEMM_FILE`, and waits for the installer's own exit code. `Start-Process` drops the 1223 "said no" code and waits on every child, as the review found in PowerShell's source. Declining is `declined`, and Try again reruns the same checked download after checking its signature again. The screen says to look in the taskbar, since the prompt can open behind Codemm. `run()` now hides its console windows.
- **Windows sign-in.** Claude Code's `auth login` opens through the Windows shell (PowerShell calls .NET's `Process.Start` with `UseShellExecute`), so its console window shows the prompts. PowerShell runs hidden and not detached. The first try, with `Start-Process` from a detached PowerShell, never ran on CI's Windows. The Mac Terminal path is unchanged.
- **Git Bash.** Not needed. Claude Code 2.1.120 dropped the requirement (it falls back to PowerShell), the tested version is 2.1.283, and Codemm runs it with `--tools ""`. This is documented, with no code change.
- **Docker command without Docker Desktop** (Homebrew's, or a stopped Colima or OrbStack). With the engine down, row 0 fails and Install Docker is offered. Docker Desktop counts as installed for all users, or for one user under `%LOCALAPPDATA%\Programs\DockerDesktop`. Open Docker Desktop opens whichever one is there.
- **Docker the learner opened.** An engine that's down while Docker Desktop's app runs (`pgrep -f /Applications/Docker.app/`, or `tasklist` for `Docker Desktop.exe`) now reads as starting, for 3 minutes from when the check first saw it. Before, only a Docker that Codemm opened got this.
- **Sign-in checks that can't answer (W-1).** `agent/signedIn.ts` asks the status command with 10 s, then once more with 60 s, since a busy Mac took 8.5 to 21 s. It is a no only when the agent says so (`loggedIn: false`, "Not logged in"). No answer, an offline marker or other output is null. Connect doesn't record null as signed out and asks again on the next look. `chosen()` lets the job run, and a failed job reports `signed-out` only on a real no. A test runs a real stand-in agent that answers late.
- **Not fixed here:** the Connect screen shows nothing while its first load waits on a slow check (renderer, outside this PR).
- **Leftovers.** At start, Codemm's own folders over an hour old are removed: `/Applications/.codemm-docker-<8 hex>` staging (with `/bin/rm -rf`) and `codemm-docker-*` downloads that a failed or declined install kept in the temp folder.
- **Sandbox row** (after #199). When core's self-test gives a `kind`, the row shows its own words instead of "Restart Docker": offline, disk, a folder to share, or Docker's sign-in helper. Offline and disk show even in Docker's first minutes. Inconclusive results show what they saw, plus Restart Docker.

  - Declining UAC was never seen (Start-Process, above).
  - An Electron request aborted before its response never settled. Electron's abort emits no error, so a stalled download hung at 0%.

## Heavy tests: big io, slow cases, JVM build tools

**What changed**

- `time_ms` ceiling raised from 30 s to 120 s (per io case, or a whole unit run). A trivial Maven + JUnit run takes 13 to 17 s in the sandbox, so with the "reference in a third of `time_ms`" rule no Maven track could install under the old ceiling: the gate told the agent to raise `time_ms`, which was silently clamped, so every retry failed the same way. At the ceiling, the probe-fast gate now says to make the command faster instead.
- io inputs can be generated: `tests/<set>/NN.gen` is a POSIX `sh` script whose output is input NN, run in the track's image before the case (30 s, outside `time_ms`). Agents can't type a million numbers into a tool call, and file maps are capped at 1 MB.
- io output per case: 64 KB → 32 MB. The host reads frames as they stream (`FrameReader`), keeps only the first 64 KB of each case, and compares the SHA-256 of the whole normalized output (`OutputDigest`). Expected outputs over 64 KB are recorded as `{ sha256, bytes, head }` in `exercise.json`. The stream cap per io set is 4 MB plus 32 MB per case. `normalizeOutput` is linear now (the old regexes backtracked quadratically on long whitespace runs).
- Gates 4 to 7 (starter, mutants, earlier solutions) stop an io set at its first error (`stopAtError`), so a too-slow mutant costs one time limit, not one per case.
- Track rules: dependencies cached at build time in a folder any user can read, used offline (Maven `-o -Dmaven.repo.local`, Gradle `--offline` + `GRADLE_RO_DEP_CACHE`), builds on a copy in `/tmp`, and the advice to call compiler and test runner directly. Exercise rules: `NN.gen`, 32 MB, slow tests.
- Fixtures: `heavy-io` track (alpine + awk), `io-prefix-big` (10^6 numbers in and out, generated), `io-slow-sum` (seconds of CPU per case), `java-maven` track (Maven + JUnit 5, offline) with `java-count-evens`.
- Walkthrough W-12: Results is the one place for test results (Try it and Check no longer print into the terminal, which is Run's); learner-facing text names the learner's files (`/work/src/x` is `x`) and says how a program ended in words, not exit codes.
- Opus review fixes: generator failures never count as a caught mutant or a recorded check; Codex `tool_timeout_sec` 1800; rebuild compares digests; bounded line memory and frame count; `/tmp/in` removed after each case; a clearer unreadable-record message.
- The Maven fixture (about 600 MB) runs only with `CODEMM_BIG_IMAGES=1`, which CI sets.

**Verified**: typecheck (core and desktop); the core unit suite; the affected desktop renderer tests; Docker: `test/docker/heavy.test.ts`, `judge.test.ts`, `app.test.ts`, `gates.test.ts`. Times are in the PR; the machine's load average was about 75 on 8 cores throughout, so they're pessimistic.
