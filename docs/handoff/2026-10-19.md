## "Docker stopped" while Docker is up (core and desktop)

Branch `claude/laughing-swanson-682999`.

- **Codes, not wording.** Every error for this computer's problem carries a stable code (`src/errors.ts` `INFRA`, via `infraError`), and its kind follows from it. `codemm mcp` writes `codemm:<code or kind>` as a failed tool result's first line, and a write that runs out of space is `host-disk` there. The desktop (`core/failures.ts`) reads only that code: `CodemmError.code` in-process, the first line over MCP. It never reads the wording, or the build logs, runner output and lesson-example stderr that messages quote. `GateError` no longer takes an infrastructure kind from its details.
- **Busy isn't stopped.** `runtimeState` and `runtimeDown` give `docker info` 20 s, then ask a silent engine, or one that answers it isn't ready (a 500 or EOF while Docker Desktop resumes), once more for 60 s. The judge, Run, inspect, list, the leftover cleanup and the desktop's probe (`wire.ts`) use them. "Stopped" is said only when the runtime says so; it names a paused Docker Desktop, socket permission and a CLI context pointing elsewhere.
- **Named refusals.** `docker run` exit 125 is named in fixed phrases (`startRefusal`): fewer than 2 CPUs, the logging driver, file sharing, Docker's disk, the network. The CLI's text never leaves. Exit 126/127 before the driver printed anything is the track image's (no `/bin/sh`). A flood is graded before a slow removal. The memory-kill lookups wait 60 s.
- **Track builds.** `buildProblem` also reads Docker's credential helper, Docker Hub's rate limit, interception-style certificate errors, timeouts, dropped downloads and `proxyconnect`, each with its own code.
- **The desktop says which.** Stopped, "Docker is busy or not answering.", "Docker couldn't run that. Try again, and restart Docker if it happens again.", "Docker ran out of disk space." (Docker's) apart from "Not enough disk space" (this computer's), and a rebuild stall with Go to Tracks. A failed setup offers Stop for Docker problems. A cleanup failure is Docker's, not the agent's. Try it's failure says "Try it didn't run".
- **Setup and lesson failures say why (walkthrough W-9, W-11).**
  - A retry proposal's dialog starts with why the last try failed: "The last try didn't build." and the like, from the failed gate's name only (`views.ts` `setupWhy`).
  - The dialog's decline is always "Not now", and its disclosure reads "Show the files".
  - A lesson job whose agent failed keeps the lesson's row ("Codemm couldn't write this lesson." with Try again; LessonState `failed`, stall `lesson`) and blames no agent.
- **Review fixes:**
  - Every failed MCP result now starts with Codemm's own `codemm:` line (`codemm:error` when there's no code), so an agent's YAML can't forge a code.
  - Jobs read codes only from Codemm's own tool calls.
  - A busy Docker no longer holds a job's end (or quitting) on a cleanup, and the cleanup reads the list error's code instead of asking Docker again.
  - Promoting a rebuilt image has a code.
  - The 126/127 rule applies only when the runtime says /bin/sh isn't there.
- **The app log** carries `cause=<code>` on `job-end`, `setup-failed`, `not-counted` and IPC errors; never core's text.
