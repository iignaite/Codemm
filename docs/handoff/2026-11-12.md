# 2026-11-12

## The roadmap shows before its review ends

**Why**: the app's own log (the owner's Mac, beta.10, Claude Opus) showed that a new learner waited for research (157 s) and then the roadmap review (112 s) before seeing anything: 4.5 minutes of a first run of about 5. Setup and the first activity already run in the background while the first lesson is written (desktop DESIGN §3.2), so the review was the largest wait the learner could not use.

**What changed** (desktop DESIGN §3.2 and §4.9):

- Research is done once its sources save, and the roadmap opens at once. The review then runs in the foreground lane while the learner reads the roadmap.
- The learner's first edit, change request or Approve stops the review and waits until its agent is gone, then saves (`saveConcepts` in `live.ts`). The learner's roadmap always wins. A review whose agent survives its cancel still refuses the edit with "The roadmap is still being checked. Try again in a moment."
- The review starts before research reports done, so an edit always finds it to stop.
- The editor says "Codemm is double-checking this path. You can edit or approve it now." while the review runs. If the review ends before any edit, the editor reads the draft again, so the review's corrections show.
- The sidebar opens a running review in the roadmap editor, not on the research screen, where a finished research would start again. The research screen shows research progress only.
- The mock plays the review beside the roadmap and stops it on an edit or Approve, as live does.

**Verified**: desktop `npm run typecheck`, and the full desktop Vitest suite passed twice (1109 passed, 11 skipped). Each new test failed first: the review running beside a shown roadmap, an edit, change request or Approve stopping it (with a review save that lands during the stop), the refused edit when the review can't be stopped, the editor's note and reload, an edit kept when the review ends later, and the sidebar opening the editor. Two older tests now wait for the review, which ends after research reports done. One unrelated renderer test (`lessons.test.tsx`, io example in the terminal pane) failed once under full-suite load and passed 5 times on its own.

**Not verified**: the e2e and packaged suites (the Electron binary wasn't installed here), and a real first run with an agent. The new time to the roadmap should be research alone, about 0.5 to 2.5 minutes in the logged runs; measure it with the app log's `job-start` and `job-end` lines.
