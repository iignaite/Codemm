# 2026-11-12

## A reason to come back: practice time and the next review

**Why**: the app's update checks fell from about 74 a day in the friends' beta (late October) to under 2 a day after 31 Oct. Learners didn't come back. Reviews come due 1, 3, 7, 21 and 60 days after mastery, but nothing outside the app reminded anyone, and the review card and streaks were cut from 1.0 (desktop DESIGN §12).

**What changed** (desktop DESIGN §3.2 and the new §4.15):

- **Practice time.** The course map's side column has a "Practice time" card: a time (default 19:00) and "Every day" or "Weekdays". Save to calendar asks where to save, with the system's save dialog, and writes `Codemm practice.ics`: one repeating 30-minute event, "Practice with Codemm", at that local time, with a reminder. Its description names the course and says a due review comes first, then the next topic. Codemm keeps no copy and opens nothing. Cancelling saves nothing.
- The file is built in `main/calendar.ts` (RFC 5545: CRLF, TEXT escaping, folding at 75 octets without splitting a character, floating local time, today if the time is still ahead, otherwise tomorrow).
- IPC `savePracticeTime({ time, repeat })` validates `HH:MM` and the two choices; the renderer never names a path. `wire.ts` shows the save dialog.
- **Review line.** A passing Check that leaves the topic with a scheduled review says when under "You mastered …": "Review tomorrow." or "Review in N days.", from core's `reviewDue`, with the same day count the course map uses (`reviewDays` in `courseView.ts`).
- A file of review dates was not built: core knows only each topic's next review, so it would be out of date after the first one. §4.15 says so.

**Verified**: desktop `npm run typecheck`, and the full desktop Vitest suite (1115 passed, 11 skipped). Each new test failed first: the calendar file (start today or tomorrow, a month end, weekdays, escaping and folding with multibyte characters), the IPC check, the main-process save and cancel, the review days in a check, the results line, and the card. The built app on the mock showed the card on the course map and its saved message.

**Fixed after review**: a weekdays series now starts on the next weekday, not a weekend. The chosen time is written as chosen, so a time in an hour a clock change skips isn't moved. A lone carriage return and other control characters can't reach the file. Each course keeps one event series (a stable UID and a growing SEQUENCE). The renamed course name is used, and a file that can't be written says so in words instead of the general error screen.

**Not verified**: the real save dialog and an import into a calendar app (Calendar, Outlook, Google Calendar). The mock saves no file.

**Next**: import a saved file into Calendar on macOS and Outlook on Windows. Then the "Today" card (reviews due, days practised this week) from the marketing report's R4.
